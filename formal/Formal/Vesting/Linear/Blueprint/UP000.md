# UP-000 standalone action reachability candidate

For the current public workflow, use the
[UP-000 run guide](../../../Properties/Universal/UP000/README.md). It selects the
original vesting artifact with native TxM-007/008 and preserves these bounded
existential claims. The sections below retain the standalone checkpoint's
provenance, outcomes, and follow-up scope; they are not fresh workflow evidence.

This candidate asks whether the pinned linear-vesting validator accepts at least
one model-valid Claim and at least one model-valid Cancel within 1,000,000 CEK
steps. [SomeAccepted.lean](SomeAccepted.lean) preserves both original existential
claims. Each claim ranges over the symbolic fields of its fixed transaction model
in [Tx.lean](Tx.lean).

The claims, types, and transaction models come from Irfan's work in
[PR #44](https://github.com/no-witness-labs/contracts-library/pull/44) at `99a5734`.
[PR #53](https://github.com/no-witness-labs/contracts-library/pull/53) extracted them
for [issue #22](https://github.com/no-witness-labs/contracts-library/issues/22).
This standalone checkpoint retains that scope and the existing SMT trust boundary.

## Run the standalone checks

From `formal/`, build the supporting modules, then run the primary file directly
to execute both checks afresh. Preserve the committed dependency pins when
preparing the checkout. The proof command uses four Lean workers and a five-minute
wall-clock limit; `Elab.async=false` checks the declarations in order.

```sh
lake build Formal.Vesting.Linear.Blueprint.Types Formal.Vesting.Linear.Blueprint.Tx
timeout --kill-after=5s 300s lake env lean --threads=4 --json -DElab.async=false Formal/Vesting/Linear/Blueprint/SomeAccepted.lean
```

Expected: two `Valid` observations, for `someAccepted_claim` and
`someAccepted_cancel`, and exit 0. A timeout leaves the result unresolved.
The wall-clock limit is separate from the 1,000,000 CEK-step bound, which is not
a ledger CPU or memory budget. Successful Blaster proofs retain its
`blasterProven` SMT trust assumption.

## Run the negative control

[RejectingControl.lean](../../../Properties/Universal/UP000/Tests/Standalone/RejectingControl.lean) replaces only
the program with a synthetic UPLC lambda that errors for every context. It retains
the Claim and Cancel models, model-validity condition, argument encoding, and CEK
bound. It asks the same two existence questions against that rejecting program.

```sh
timeout --kill-after=5s 300s lake env lean --threads=4 --json -DElab.async=false Formal/Properties/Universal/UP000/Tests/Standalone/RejectingControl.lean
```

Expected: two `Falsified` observations, for `someAccepted_claim_control` and
`someAccepted_cancel_control`, and a nonzero Lean exit. This deliberate proof
failure is the successful control outcome. An import error, unrelated compilation
error, solver error, or timeout does not satisfy the control. The file is outside the
`Formal` library so routine library builds do not include it.

## Scope and checkpoint 2

Claim has two inputs and two outputs; Cancel has two inputs and one output.
Both models use one vested asset under fixed `policyA`, key credentials, one
signer, and a validity range with a finite lower bound and no upper bound.
They do not include reference inputs, minting, or withdrawals. The symbolic fields
vary within these structures; the claims do not cover arbitrary transactions or
other validators.

`validScriptContext` is the pinned ledger model's validity predicate. A `Valid`
observation establishes an accepted instance within that model and bound; it does
not establish deployed-ledger reachability or general validator safety. These
claims neither require every output to contain at least 1 ADA nor print a working
transaction. Both requirements remain deferred to checkpoint 2 under
[issue #22](https://github.com/no-witness-labs/contracts-library/issues/22).

App integration belongs to checkpoint 2 under
[issue #96](https://github.com/no-witness-labs/contracts-library/issues/96).
Adoption of the native model bank and broader model coverage remain under
[issue #89](https://github.com/no-witness-labs/contracts-library/issues/89).
Generalization beyond this validator and optimization also remain checkpoint-2
work. This candidate leaves the broader action-reachability issue open.
