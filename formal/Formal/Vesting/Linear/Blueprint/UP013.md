# UP-013 standalone unbounded-range candidate

This candidate checks the fixed linear-vesting Claim and Cancel models. Given a
model-valid context accepted by the validator, it replaces only the validity range
with `rangeAlways`, the fully unbounded range `(-∞, +∞)`. If the changed context is
also model-valid, the validator must explicitly reject it within 1,000,000 CEK
steps. Separate applicability obligations require a valid accepted baseline and a
valid changed context for each action. Exhausting the CEK bound does not establish
rejection; the bound is not a ledger CPU or memory budget.

The definitions and transaction shapes come from Irfan's work in
[PR #44](https://github.com/no-witness-labs/contracts-library/pull/44) at `99a5734`.
[PR #21](https://github.com/no-witness-labs/contracts-library/pull/21) adopted them
for [issue #34](https://github.com/no-witness-labs/contracts-library/issues/34).
[UnboundedRange.lean](UnboundedRange.lean) retains all four statements from the
candidate at `b1b7e5c745ad3729b8a7e36347dc183a3eeb45fc`.
[Tx.lean](Tx.lean) retains the original transaction models.

## Run the candidate

From `formal/`, build the supporting modules, then run the source directly to
obtain fresh proof observations. The proof and control files run their declarations
sequentially with four Lean workers and a five-minute wall clock limit per file.

```sh
lake build Formal.Universal.CandidateHelpers Formal.Vesting.Linear.Blueprint.Types Formal.Vesting.Linear.Blueprint.Tx
timeout --kill-after=5s 300s lake env lean --threads=4 --json Formal/Vesting/Linear/Blueprint/UnboundedRange.lean
```

Expected: four `Valid` results and exit 0, in this order:

| Declaration | Obligation |
| --- | --- |
| `unboundedRange_claim` | Claim rejects after the range mutation. |
| `unboundedRange_claim_applies` | Claim has a valid accepted baseline and valid mutation. |
| `unboundedRange_cancel` | Cancel rejects after the range mutation. |
| `unboundedRange_cancel_applies` | Cancel has a valid accepted baseline and valid mutation. |

A timeout leaves the result unresolved. Blaster uses SMT verification through
`blasterProven`; these checks retain the existing dependency trust assumptions.

## Run the accepting control

[AcceptingControl.lean](../../../../tests/UP013/AcceptingControl.lean) replaces the
validator with a synthetic UPLC program, `λctx. unit`. It retains the same Claim
and Cancel contexts, argument encoding, validity premises, mutation to the fully
unbounded range, rejection semantics, and CEK bound. This program accepts both the
baseline and changed context. Blaster must falsify the two rejection claims and
verify both applicability obligations.

```sh
timeout --kill-after=5s 300s lake env lean --threads=4 --json tests/UP013/AcceptingControl.lean
```

Expected observations, in order:

| Declaration | Result |
| --- | --- |
| `unboundedRange_claim_control` | `Falsified` |
| `unboundedRange_claim_control_applies` | `Valid` |
| `unboundedRange_cancel_control` | `Falsified` |
| `unboundedRange_cancel_control_applies` | `Valid` |

The expected overall exit is 1 because the file contains two deliberately false
theorems. That verification failure is the successful control outcome only when
all four observations match. An import, compilation, or solver error, or a timeout,
does not establish the control outcome. The file is outside the `Formal` library
so routine library builds do not include it.

## Scope and later work

Claim uses two inputs and two outputs; Cancel uses two inputs and one output.
Both use one vested asset under fixed `policyA`, key credentials for the beneficiary
and locker, and one signer.
Their baseline range has a finite lower bound and no upper bound. The mutation
changes only that range to `(-∞, +∞)`; it does not quantify over every range with
a missing lower bound. The proofs cover these models and the pinned validator,
without establishing arbitrary transaction coverage or ledger reachability.

Checkpoint 2 retains the following work:

- Broader range coverage and property meaning under
  [issue #34](https://github.com/no-witness-labs/contracts-library/issues/34).
- Reusable model authoring under
  [issue #89](https://github.com/no-witness-labs/contracts-library/issues/89).
- General typed data and parameter preparation under
  [issue #88](https://github.com/no-witness-labs/contracts-library/issues/88).
- App integration and reconciliation with the native property and model banks
  under [issue #96](https://github.com/no-witness-labs/contracts-library/issues/96).
