# UP-002: unsigned spends

UP-002 asks whether every unsigned spend in the existing `Holes` model fails to
return unit within **5,000,000 CEK steps**. It retains the four historical formulas
for the good vault, buggy vault, and linear vesting Claim and Cancel. Fuel
exhaustion counts as nonacceptance. This is distinct from UP-012's mutation of an
accepted signed transaction and does not establish explicit CEK error rejection.

The primary propositions still quantify over every `h : Holes` and assume
`sig1 = false`, `sig2 = false`, `out1Foreign = false`, model validity, and
`ledgerFloor`. The only model change is the owner-approved replacement of each
placeholder script identity by the actual 28-byte V3 script hash. No field,
guard, amount domain, shape choice, or execution bound was narrowed.

The nine prototype modules now live beside these tests in
`tests/UP002/Prototype/`. Their module/namespace prefix is
`tests.UP002.Prototype`. The older top-level `Universal/` location is retired;
the shared `Formal/Universal/` library is separate. This relocation preserves
the model and proposition meanings, artifacts, guards, and bounds.

The three `Base.lean` files spell the existing value concatenation as
`List.append`. The current ledger library defines `Value` as a distinct named
list type, so the earlier overloaded `++` call no longer elaborates. The explicit
call retains the same entries, order, and map encoding.

inputs, outputs, and signers; no reference inputs, withdrawals, certificates,
datum hashes, or input tokens; a single datum-list entry; and no finite upper
validity bound. Vesting credentials use the existing constructor choices.
Permissionless validators can intentionally falsify this candidate.

The proof jobs print theorem axioms. The pinned CEK dependency already emits a
`sorry` declaration warning; a successful build does not remove that dependency
trust. These changes add no admitted proofs or axioms.
